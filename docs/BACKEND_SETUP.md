# 第一版后端：邮箱登录 → 图片投稿 → 审核 → 展示

## 当前状态和范围

2026-11-03 已在本地完成 Supabase 连接、Resend 自定义 SMTP、邮箱数字验证码登录、真实 PNG 上传和待审核记录持久保存的联调；已确认待审核投稿不出现在公开接口。发信子域名为 `mail.pulsebeat.space`，保留原网站域名解析。管理员授权、跨账号线上审核及 Vercel 线上部署仍需按下文完成。

没有配置时页面会明确显示“后端尚未配置”，不会假装上传成功。新环境请按下面步骤安装；已配置的项目不要重复执行首次安装迁移。

- 不支持视频，也不会把用户文件提交到 GitHub。
- 使用 Supabase 官方客户端，浏览器直接上传文件到私有存储桶；不经过 Vercel 函数转发。
- 头像/封面各 1 张、各最大 5MB，展示图片恰好 3 张、每张 8MB、合计 24MB，单次总量 90MB。
- 一个邮箱账号每天最多新建 3 份投稿；失败可继续同一草稿，不重复占配额。
- 学生只能读取自己的投稿。待审核/退回的文件不对访客开放。管理员才能通过、退回或下架。
- 公开接口只输出作者显示名、年级、作品资料和已审核文件，不输出邮箱、学号、认证账号 ID 或审核意见。
- 审核通过后进入“全部作品”和作者页。学生柜子、年级筛选、个人主页和光盘库根据已发布投稿自动生成；同一公开作者 ID 的作品归入同一柜子，不以姓名匹配账号，避免同名串档。原有静态学生资料保留，新账号不会仅凭同名覆盖原柜子。管理员仍需核对投稿身份后再通过。
- 旧作品与审核通过的新投稿共用 3D 光盘及详情版式。新投稿自动把封面作为光盘正反面贴图，简介、展示图和 PDF 使用统一详情模板，不需要逐件制作模型。柜子编号、颜色和装饰只是投稿里的样式偏好，不占用/覆盖现有 8 个柜子。

## 1. 创建 Supabase 项目

1. 在 [Supabase Dashboard](https://supabase.com/dashboard) 新建一个专门用于测试的项目，选择适合用户所在地的区域。
2. 保存数据库密码到你自己的密码管理器，**不要发到聊天或写进代码**。
3. 等待项目就绪，进入 SQL Editor，完整执行一次：

   `supabase/migrations/202611030001_submissions.sql`

这是首次安装脚本，不要在已经装好的项目重复执行。后续变更应另写迁移，不要删除生产表重装。

脚本会创建私有 `submissions` 存储桶、投稿/附件/管理员表，以及带权限检查的数据库函数。不要将桶改成 Public，不要关闭 RLS，不要给普通用户增加表的写权限。

## 2. 配置邮箱验证码

1. Authentication → Sign In / Providers 中开启 Email，保留邮箱确认，关闭不需要的匿名登录。
2. Authentication → Email Templates，把 **Magic Link** 和 **Confirm signup** 模板改为显示验证码，例如：

   ```html
   <h2>FENG 邮箱验证码</h2>
   <p>你的验证码是：{{ .Token }}</p>
   <p>不是你本人发起的请求，请忽略此邮件。</p>
   ```

   当前配置使用数字验证码。前端同时兼容邮件登录链接，链接返回当前站点的 `/submit`；使用链接时也需将完整回调地址加入允许列表。
3. URL Configuration：Site URL 填正式网站域名；本地开发地址可加入允许列表 `http://localhost:5174`、`http://127.0.0.1:5174`、`http://localhost:5174/submit`、`http://127.0.0.1:5174/submit`。
4. **尚未配置 SMTP 时，先用 Supabase 项目团队成员的邮箱测试**。内置邮件服务只向项目团队成员发送邮件，且整个项目通常每小时仅 2 封；这不是前端故障。向普通学生开放前必须配置 Custom SMTP 和发件域名，再检查 Authentication 的邮件频率限制。
5. 初期只邀请少量测试学生，确认收件、权限和存储配额后再开放；公开注册前建议启用 Supabase 的验证码/反滥用防护并将 captcha token 接入发送验证码流程（本版未接第三方 CAPTCHA）。

参考：[邮箱验证码](https://supabase.com/docs/guides/auth/auth-email-passwordless)、[邮件服务限制](https://supabase.com/docs/guides/auth/auth-smtp)。

## 3. 配置本地公开连接信息

项目 Settings / Connect / API Keys 中找到：

- Project URL，类似 `https://你的项目.supabase.co`
- **Publishable key**（`sb_publishable_...`，或兼容的旧 `anon` key）

在项目根目录新建 `.env.local`，按 `.env.example` 填写：

```dotenv
VITE_SUPABASE_URL=https://你的项目.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=你的公开密钥
```

`.env.local` 已被 Git 忽略。`VITE_*` 会打包到浏览器，所以**绝不能填 `service_role`、`sb_secret_...` 或数据库密码**。本版根本不需要在前端/服务器配置管理员私钥；权限由 RLS 和 RPC 校验。

重新启动开发服务器，再打开 `/submit`。Node.js 建议使用 22 或更新版本：

```sh
pnpm install --frozen-lockfile
pnpm dev -- --port 5174
```

## 4. 设置你的管理员账号

1. 先在网站 `/submit` 用自己的邮箱发送验证码并登录一次。
2. 在 Supabase → Authentication → Users 确认自己的用户已出现，复制自己的 **User UID**。
3. 在 SQL Editor 执行（只替换 UID，不要用公开邮箱匹配或用户自填角色）：

   ```sql
   insert into public.submission_admins(user_id)
   values ('这里替换成你自己的用户UID')
   on conflict do nothing;
   ```

4. 刷新 `/submit`，会出现“进入管理员审核”。审核地址为 `/review`。
5. 其他人即使知道 `/review`，没有管理员授权也不能读取全部投稿、通过作品或自封管理员。

只有项目拥有者能执行管理员授权。取消某个管理员时，在 Dashboard 的管理员表删除其授权行即可，不要删除认证用户或作品文件。

## 5. 跑通第一件投稿

1. 用测试学生邮箱登录 `/submit`。
2. 直接填写学生和作品资料，上传个人头像、封面以及 3 张展示图。柜外装饰可选择“无”。
3. 点击“上传并提交审核”，看到逐文件进度和“投稿成功”。“我的投稿”显示“待审核”。
4. 未审核时，用退出登录/另一浏览器确认：公开作品列表看不到投稿，也打不开待审核文件。
5. 用管理员账号登录 `/review`，核对学生身份、文字和文件后，点击“通过并发布”。**审核动作会对外发布姓名、年级和作品文件，真实学号和邮箱不会公开。**
6. 刷新 `/works`，看到新的唱片卡片；点击进入图文详情，再点击作者进入 `/creators/<公开作者ID>`。
7. 用第二个学生账号确认：无法读取第一个账号的“我的投稿”和未审核文件，无法调用审核函数。
8. 在管理员“已发布”中下架，刷新公开页面，确认作品移除。

文件预览使用 5 分钟签名链接。下架后不再签发新链接，已发出的链接最多仍可在其有效期内访问；已下载的文件无法远程收回。超过有效期的页面可刷新重新读取文件。

## 6. 配置 Vercel

在对应 Vercel 项目的 Environment Variables 中添加同样两项公开配置，按需选择 Preview/Production，然后重新部署。Vite 在构建时读取变量，只保存变量、不重新部署不会生效。

先部署 Preview 跑通测试，再发布 Production。`vercel.json` 已覆盖 `/works/*`、`/creators/*` 和 `/review` 的 SPA 刷新规则。

## 7. 故障处理

- “后端尚未配置”：检查变量名称、值和是否重启/重新部署。
- 收不到验证码：检查团队成员邮箱限制、SMTP、邮件模板、垃圾邮件和邮件发送频率；不要连续反复发送。
- `function ... does not exist`：SQL 迁移没执行、执行失败或连接错了项目。
- 无审核权限：确认当前登录邮箱对应的 UID 已在 `submission_admins` 中。
- 上传中断：不清空表单，直接重试；刷新后先在“我的投稿”检查，点“继续填写这份投稿”，重新选文件再提交。浏览器不能恢复本地文件选择。
- 文件成功但最终请求超时：先查看“我的投稿”，避免重复提交；最终提交 RPC 支持安全重试。
- 一个旧草稿已提交却仍被本标签页记住：先确认“我的投稿”状态，在浏览器关闭该标签页后重新打开，再创建下一份；不要为了重试删除已提交作品。
- 存储接近配额：从 Storage Dashboard 清理确认无用的草稿文件。不要只通过 SQL 删除 `storage.objects` 元数据（那不等于删除实际文件），也不要清理 pending/approved 投稿的文件。
- 本版验证 MIME、数量、路径和文件大小，不提供病毒扫描/恶意 PDF 检测；PDF 仅作为下载附件。正式大规模开放前应增加文件扫描、验证码、账号准入和监控告警。

## 8. 本地测试

```sh
pnpm test
pnpm build
```

`tests/submissionDatabase.test.js` 使用嵌入式 PostgreSQL，验证实际 SQL/RLS：跨账号隔离、不能自封管理员、审核前不可公开、审核/下架、已提交文件不能改写、文件限制和每日配额。它不依赖真实 Supabase 账号，也**不能替代实际的邮件和云存储联调**。

第一版没有创建收费资源、没有开通邮件服务、没有自动授权管理员，也没有往线上上传任何真实资料。


## 新版投稿规则

学生可直接填写作品，柜外装饰保留；不再要求选择柜子编号或填写学号。
头像、封面、恰好 3 张展示图片、团队成员与分工、作品简介均必填，不再提供 PDF 上传。
部署新规则时须执行 `supabase/migrations/202611040001_required_submission_materials.sql`，让数据库同步强制材料数量和分工。
该迁移不追溯修改旧投稿；新投稿学号字段写入空字符串。前端暂保留旧 RPC 的内部兼容参数，不向学生采集学号。

## 我的作品与修改稿

- `/submit` 右下角“我的作品”使用 `public/assets/my-works-folder.png`，进入 `/my-works`；其他页面保留上传入口。
- 登录后只查询当前账号的投稿，可筛选状态、读取审核意见、修改文字和柜外装饰、替换头像/封面/3 张展示图。不更换图片时复制保留现有图片。
- 保存产生私有修改稿并重新审核，原版继续展示。修改稿通过后替换公开版本，作品公开地址保持不变；被退回则继续展示原版。
- 启用实际保存前，依次应用增量迁移 `202611040001_required_submission_materials.sql`、`202611040002_work_revisions.sql`。不要重复执行初始建表迁移。迁移应与前端版本一起发布。
- 编辑与审核依赖账号归属和数据库权限校验，内部最终提交/审核函数禁止客户端直接调用。所有修改图像均存入新的私有投稿目录，不覆盖已发布文件。
